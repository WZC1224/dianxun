# 点讯 — Idea One-Pager

## Problem Statement

How might we 让零售加密交易者少切 3–4 个 App，仍能在开仓前同时拿到快讯、参考点位、多空情绪与事件日历？

## Variations considered

1. **纯快讯聚合** — 对标律动；无差异，不选。
2. **纯信号/点位** — 合规与信任成本高；缺上下文。
3. **全功能交易终端** — 过大，小团队死。
4. **推荐方向：盯盘驾驶舱** — 快讯流 + 主流币点位卡 + 多空条 + 日历；不做下单。
5. **社群跟单** — 运营重，MVP 不做。
6. **AI 聊天荐币** — 幻觉/合规风险，延后。

## Recommended Direction

**点讯 = 加密盯盘驾驶舱（参考层，非执行层）。**

- 首页：顶部主流币迷你点位条 + 实时快讯流（市场习惯：打开先刷讯）。
- 点位 Tab：买入/卖出/止盈/止损参考，附方法说明与免责。
- 多空 Tab：主流合约多空比、资金费率摘要。
- 日历 Tab：未来 7–30 天大事。

差异化：点位与快讯同屏上下文，而不是又一个新闻站或又一个 CoinGlass 壳。

## Key Assumptions

1. 用户接受「规则化技术点位」作为 v1，不要求人工分析师。
2. 第三方 API（新闻/多空/日历）可商用或有免费档够 MVP。
3. PWA 对目标用户可接受（可后补原生壳）。
4. 明确免责声明可降低合规暴露到可接受水平（仍非法投顾问）。

## Kill risks

- 点位被当成「保证赚钱信号」→ 必须文案 + UI 弱化「保证」。
- 数据源断供/限流 → 适配层 + mock + 多源接口。
- 范围膨胀成 TradingView → 边界写死。

## MVP Scope

- 四 Tab：快讯 / 点位 / 多空 / 日历
- Top 5–10 币点位
- 游客可用；本地自选
- 免责声明全局可见

## Not Doing

自动交易、跟单、完整图表终端、支付会员、多语言、原生双端独立工程（首版）
